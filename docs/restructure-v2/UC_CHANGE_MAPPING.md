# UC change mapping - Compact V2

Updated 25 November 2026. Requirement mapping is not an acceptance certificate. Historical UC IDs and names are preserved. OLD_ACTOR is extracted verbatim from the Primary Actors row in the original SRS HTML tables; it is not inferred from current code. NEW_ACTOR describes approved responsibility, not an unconditional permission grant.

Sources: [Master section 40](OWNER_REQUEST_PART_4.md), [D01-D12](DECISION_AND_BLOCKER_REGISTER.md), [later Owner UI decisions](OWNER_UX_DELTA_20261125.md), [SRS baseline](../requirements/HotelOps_SRS_DRAFT.md) and [approved change notes](../requirements/SRS_CHANGE_NOTES.md). Later explicit Username-only decisions supersede earlier employee-code/email descriptions.

Classification values are exactly RETAINED, MODIFIED, MERGED, REMOVED, RESTORED, NEW, BLOCKED. RESTORED refers to retained maintenance responsibilities recovered from the baseline; it does not declare every historical account migrated and tested. MERGED refers to DH management responsibility consolidated into OM, not deletion of the historical UC. NEW entries have no invented UC number.
