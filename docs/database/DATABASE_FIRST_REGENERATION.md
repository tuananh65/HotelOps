# Database First regeneration

Use the repository's .NET SDK and installed `dotnet-ef` version matching the
EF Core packages. Configure `ConnectionStrings:HotelOpsDb` locally with .NET
User Secrets. Never put credentials or local connection strings in source.

Before applying an approved SQL patch, verify `SELECT @@SERVERNAME` and
`SELECT DB_NAME()` against the task's target, take a backup, and review the
patch. Do not run baseline creation or seed scripts on an existing database.
Do not create EF migrations.

Run a full scaffold into an ignored temporary directory, never over source:

```powershell
$env:ASPNETCORE_ENVIRONMENT = 'Development'
$env:DOTNET_ENVIRONMENT = 'Development'
dotnet ef dbcontext scaffold Name=ConnectionStrings:HotelOpsDb Microsoft.EntityFrameworkCore.SqlServer --project src/HotelOps.Api --output-dir obj/InventoryScaffold/Entities --context-dir obj/InventoryScaffold/Data --namespace HotelOps.Api.Entities --context-namespace HotelOps.Api.Data --context HotelOpsDbContext --no-onconfiguring
```

The current model uses default PascalCase naming and Fluent API mappings.

For FE-09 use `obj/MaterialRequestScaffold/Entities` and
`obj/MaterialRequestScaffold/Data` for the temporary output. Compare only the
approved Material Request delta and its direct navigation consequences. Preserve
existing navigation names when a new FK causes scaffold naming changes; keep
the relationship metadata generated by the temporary scaffold. Check for shadow
FK properties as well as SQL catalog compatibility. A new unique document FK
may legitimately change the generated navigation from a collection to one-to-one.
Do not add `--use-database-names` or `--data-annotations`. Inspect the existing
model again if its conventions change. `--no-onconfiguring` prevents connection
configuration from being emitted in generated C#.

Compare every generated entity and the context with the tracked versions.
The temporary scaffold is authoritative for database metadata, but **never
blindly overwrite** the tracked generated tree. Synchronize only entities,
properties, mapping sections, navigations, and DbSets directly caused by the
approved schema delta. Preserve unrelated code and report pre-existing drift.

Check SQL catalog metadata for types, lengths, precision, nullability, keys,
foreign keys, and indexes. For rowversion, verify SQL type timestamp/rowversion
and EF `IsRowVersion().IsConcurrencyToken()` metadata/value generation, rather
than adding an ordinary byte array property.

After synchronization:

```powershell
dotnet build HotelOps.slnx
dotnet test HotelOps.slnx
git diff -- src/HotelOps.Api/Entities src/HotelOps.Api/Data/HotelOpsDbContext.cs
git diff --check
git status --short
```

Review each generated-model change against the approved patch. Validate the
affected functionality against real SQL Server. Remove the temporary scaffold
directory after resolving and verifying its absolute path under the project's
`obj` directory. Confirm no temporary artifacts or secrets appear in Git status.
