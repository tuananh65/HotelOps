## Important SRS/schema conflicts

- SRS transition appendix around 16286 uses CleaningTask PENDING_ASSIGNMENT, ASSIGNED, ON_HOLD, PENDING_INSPECTION, REWORK_REQUIRED; the current SQL CHECK has only PENDING/IN_PROGRESS/COMPLETED/CANCELLED.
- SRS Inspection has ASSIGNED/INSPECTING/PENDING_CONCLUSION/PASSED/FAILED; SQL uses PENDING/IN_PROGRESS/COMPLETED/CANCELLED plus separate result.
- SRS Task transitions include PENDING_ASSIGNMENT/ASSIGNED/ACCEPTED/PAUSED/PENDING_VERIFICATION/CLOSED and reopen CLOSED -> ASSIGNED; current operational_tasks CHECK has the five values above. Review responsibility cannot be inferred from COMPLETED alone.
- SRS InternalRequest starts PENDING_ACCEPTANCE then ACCEPTED, whereas SQL permits DRAFT/SUBMITTED and lacks those values. Workday WORKING/ENDED is specified but no corresponding current entity/table was found.

These conflicts require lifecycle mapping/schema decisions, not an invented state conversion in a deactivation query.

SRS UC-119 / GBR-151 specifically keeps the sender responsible until the designated new handler acknowledges handover. No InternalRequestHandover entity/table or writer was found: InternalRequestEvent has actor/status/note/time only, without a structured designated receiver/acknowledgment field. Do not pretend that simply ending the old assignment or reading an event actor proves an acknowledged transfer. UC-118 / GBR-150 also states that linked work does not close the originating request, so checking linked tasks alone is incomplete.

Draft eligibility evidence also exists: GBR-046 specifies Active Housekeeping Staff in the room's Branch/Housekeeping department; GBR-058 specifies an eligible Active inspection supervisor and one open inspection per cleaning cycle; GBR-126 specifies an Active executor in the task's department/Branch. Future writers must reconcile these with approved role/scope changes, not replace them with a universal User ACTIVE check. Exact employment-status handling remains a separate decision.
