# Đối chiếu nguồn và các điểm cần xác nhận

Các điểm sau được giữ thành danh sách riêng. Không sửa SQL, Business Rules hoặc System Messages để làm khớp front-end.

| Vị trí | Khác biệt | Ảnh hưởng và cách bản sửa xử lý |
|---|---|---|
| SRS II UC-020, V GBR-039/043/044; SQL `rooms.operational_status`, extended property cuối file | SRS phòng mới Pending Cleaning; SQL mặc định AVAILABLE và ghi chú AVAILABLE/DIRTY/CLEANING/INSPECTION/READY/OUT_OF_SERVICE | Cần mapping/khởi tạo phía server. Client không tự coi AVAILABLE là Ready và không ghi status từ Room form |
| SRS V Status Catalog/Transitions; SQL `cleaning_tasks`, `cleaning_reworks`, `room_inspections` | SQL mặc định PENDING; SRS phân biệt PENDING_ASSIGNMENT, PENDING_ACCEPTANCE, ASSIGNED | Server phải trả mã SRS và chọn trạng thái khởi tạo đúng nghiệp vụ; các action không tự bật trên trạng thái chưa thống nhất |
| SRS V Incident/Task/InternalRequest/Stocktake; SQL `incidents`, `operational_tasks`, `internal_requests`, `stocktakes` | SQL OPEN, TODO, DRAFT; SRS PENDING_TRIAGE, PENDING_ASSIGNMENT, PENDING_ACCEPTANCE, IN_PROGRESS tương ứng | Không có thay status chung trong client; server controller/service phải quản lý transition |
| SRS V GBR-005; toàn bộ SQL | Không tìm thấy `row_version`/SQL rowversion hoặc token concurrency được định nghĩa | DTO đề xuất có rowVersion; action ghi bị chặn nếu không có. Backend cần chọn cơ chế concurrency, không phải client tạo số version |
| SRS II/V workday, work interval, time correction, task series, replenishment, escalation, shift handover, notification retry | SQL chưa có cấu trúc chuyên biệt tương ứng; có ca và attendance nhưng không tương đương work interval | Những endpoint này là đề xuất nghiệp vụ. Nhóm back-end cần xác nhận lưu trữ và atomicity; không dùng localStorage để bù phần thiếu |
| SRS GBR-019/020/023; SQL `users` | Chưa có failed attempts, locked_until, trạng thái và thời hạn temporary password như SRS | Phải chốt cơ chế lưu/xử lý trong backend. Front-end chỉ nhận trạng thái/lỗi và bắt đổi mật khẩu theo session |
| SQL `user_sessions.refresh_token_hash`; source Program/controller | Có tên cột refresh token nhưng không có login/refresh controller được cung cấp | Không kết luận đã dùng JWT hoặc có refresh endpoint. Client chỉ bật cookie/bearer sau khi được cấu hình |
| SRS II UC-017/018, UI Room Type; SQL `room_types`, `inspection_checklists` | UI có branch, standard cleaning minutes và default checklist; SQL room_types có type code toàn cục, capacity và không có các cột cấu hình UI đó | API projection/write mapping cần được chốt; không thêm cột hoặc giả định các thuộc tính UI là JSON entity SQL |
| SRS I entity identity và V GBR-086; SQL `assets.asset_code UNIQUE` | Phạm vi duy nhất của mã tài sản được mô tả chưa đồng nhất giữa mô hình khái niệm và quy tắc; SQL đang unique toàn cục | Cần xác nhận phạm vi uniqueness. Client nhận lỗi trùng từ server, không tự nới ràng buộc |
| SRS V Asset lifecycle/condition; SQL `assets.lifecycle_status/condition_status` | SRS lifecycle Active/Retired, condition In Use/Damaged/Under Repair; SQL mặc định IN_USE/GOOD | Hai khái niệm không gộp. API cần mapping riêng, client không tự sửa GOOD thành In Use |
| SRS V GBR-159, Notification; SQL `notification_recipients` | Có read_at/dismissed_at, chưa có acknowledgment timestamp rõ ràng | Acknowledge phải là endpoint riêng, không giả dùng Mark Read để thay thế |
| SRS GBR-006/007/096–109; SQL stock documents/lines/movements | Chứng từ, ledger có quan hệ nhưng chưa xác nhận server transaction/idempotency/reversal và ghi nhận losses theo dòng | Client chỉ gửi input theo operation, không tự ghi ledger/tăng tồn; server phải bảo đảm toàn vẹn và chống ghi lặp |
| SQL `floors`/`areas`; UI `locations` | Hai bảng có identity riêng, trong UI là một collection | API locations cần ID phân biệt loại, như floor:17 và area:17; tham chiếu trong DTO phải thống nhất, tránh coi hai ID 17 là cùng vị trí |
| SQL `maintenance_works`, `preventive_maintenance_runs`, `incidents`; UI Maintenance | Work ID, occurrence ID và incident ID khác nhau; prototype từng ghép các record làm một view | Read projection cần source linkage; action sửa chữa dùng incidentId, không giả định bằng workId |
| Source catalog cũ; SRS II UC-141–144 | Source cũ chỉ có 140 UC và gán list vào quyền tạo/sửa | Đã đồng bộ metadata 144 UC; thêm quyền đọc danh sách vào bốn route User/RoomType/Incident/Maintenance, không đổi nội dung quy tắc SRS |
| Source Branch form / Room actions / Generate buttons; SRS II | Prototype có Create Branch, Reactivate Room, trigger generate lịch thủ công; không phải tất cả đều có UC độc lập tương ứng | Giữ khả năng UI để đối chiếu, gắn endpoint đề xuất; action cần server capability. Không khẳng định các thao tác này đã được SRS/API thật xác nhận |
| Source `feature/BE2-incident` Program/IncidentsController/service | Hai GET thật chưa có cơ chế xác thực, phân trang hoặc scope filtering được cung cấp, và Program chưa cấu hình CORS | Phân biệt route guard client với kiểm tra server. Chưa đủ để đưa các GET này vào vận hành chỉ bằng đổi base URL |
| SRS III External API Inventory, bảng XML 214–215 | Có mẫu VNPay/SePay commerce webhook không khớp phạm vi UI quản trị vận hành khách sạn được giao | Ghi nhận nội dung cần làm rõ; không tự thêm API thanh toán hoặc gọi các webhook đó |

SRS là nguồn nghiệp vụ; SQL mô tả schema; controller/DTO thật quyết định route/JSON hiện có. Vì mới xác nhận hai GET sự cố bằng source, mọi endpoint còn lại được ghi nhãn đề xuất thay vì giả định back-end đã có.
